# Группы (папки) категорий — дизайн

Дата: 2026-06-02
Статус: согласован, готов к планированию реализации

## Контекст

AIFB — дипломный проект (Spring Boot 3.3.5 / Java 21 / PostgreSQL + Flutter Web).
Реализовано: auth, admin, финансовое ядро + цели, семейный бюджет (scope личное/семейное
через `household_id`, роли OWNER/ADULT/CHILD). Категории типизированы (INCOME/EXPENSE),
системные + пользовательские, мягкое удаление, scope-aware.

Цель — добавить **группы (папки) категорий**: объединять несколько категорий под один
«зонтик» (напр. «Коммунальные» = Свет + Вода + Интернет), чтобы позже вешать **лимит на
группу** (следующая подсистема дорожной карты). Это первая из трёх подсистем scope «D»
(группы → лимиты → авто-категоризация).

Зависит от ветки `feature/family-budget` (нужен `scope`/`household_id`).

## Согласованные решения

- **Структура (A):** одноуровневые группы; у категории необязательный `group_id` (одна группа).
  Без вложенности и many-to-many.
- **Владение (B):** группы **только пользовательские** (без системного сидинга), типизированы
  (INCOME/EXPENSE) и scope-aware (личные/семейные через `household_id`). Системных групп нет.
- **Удаление группы — жёсткое**, с авто-разгруппировкой категорий через FK `ON DELETE SET NULL`
  (у группы нет прямых транзакций; история трат живёт в категориях/операциях, поэтому
  мягкое удаление не нужно).
- **Привязка** категории к группе — через поле `groupId` в форме категории (create/update).
- **Проверки:** группа должна совпадать с категорией по **типу** и **scope**; права на семейные
  группы — как на семейные категории (OWNER/ADULT).

## Модель данных (миграция V10)

### `category_groups` (новая)
| поле | тип | примечание |
|---|---|---|
| id | UUID PK | |
| user_id | UUID NOT NULL FK→users ON DELETE CASCADE | создатель |
| household_id | UUID NULL FK→households ON DELETE CASCADE | NULL=личная, заданный=семейная |
| name | VARCHAR(80) NOT NULL | |
| type | VARCHAR(10) NOT NULL | INCOME/EXPENSE (CHECK) |
| icon | VARCHAR(40) NULL | |
| color | VARCHAR(9) NULL | |
| created_at, updated_at, version | | аудит |

Индексы: `(user_id) WHERE household_id IS NULL` (личные), `(household_id) WHERE household_id IS NOT NULL` (семейные).
Уникальность имени не навязываем (необязательно для папок).

### `categories` (ALTER)
- `group_id UUID NULL FK→category_groups(id) ON DELETE SET NULL` — при удалении группы категории
  автоматически разгруппируются.

## Backend-модуль `finance/group/`

Структура по образцу `finance/category`: `api` / `api/dto` / `domain` / `repository` / `service`.

### Эндпоинты
```
GET    /api/v1/groups?type=&scope=personal|family   список видимых групп
POST   /api/v1/groups        {name, type, icon, color, shared}   shared=true → семейная (права OWNER/ADULT)
PUT    /api/v1/groups/{id}    {name, icon, color}
DELETE /api/v1/groups/{id}    жёсткое удаление; категории разгруппируются (FK SET NULL)
```
- `list`: PERSONAL → `user_id=me AND household_id IS NULL`; FAMILY → `household_id = моя семья` (пусто, если семьи нет).
- `create`: при `shared=true` — `HouseholdContextService.requireManageSharedContent` (OWNER/ADULT), `household_id` = семья пользователя; иначе личная.
- `update`/`delete`: владение — личная (по `user_id`) или семейная (членство + OWNER/ADULT); иначе 404/403 по матрице.

### Изменения в модуле `category`
- `CreateCategoryRequest`/`UpdateCategoryRequest` — добавить опциональный `UUID groupId`.
- При указании `groupId` сервис категорий валидирует: группа существует и видима в том же scope,
  и `group.type == category.type`; иначе доменная ошибка (400) или 404. Несовпадение scope/типа → 400.
- `CategoryResponse` — добавить `groupId` (+ `groupName` для отображения, через lookup).
- При создании семейной категории с группой — группа тоже должна быть семейной (того же `household_id`).

## Frontend

Стиль — как в существующих фичах (data: Dio + модели + repo; presentation: Riverpod + страницы).

- **Новая фича `groups`** (`features/groups`): data source/repo/провайдеры + управление
  (список групп по scope, создание, удаление). Экран управления группами (или секция на
  экране категорий).
- В рамках этой фичи фронт даёт: **экран «Группы»** (список по scope + создание + удаление),
  провайдер `groupsProvider(scope)` (параметризуется `Scope`, как финансовые), и поле
  `groupId`/`groupName` в `CategoryModel` (для отображения).
- **Привязка категории к группе из UI — вне объёма этой фичи:** на фронте сейчас нет экрана
  создания/редактирования категории (категории приходят системные + создаются через API).
  Поэтому назначение `groupId` категории выполняется на уровне API; UI-выбор группы в форме
  категории появится, когда/если будет добавлен экран управления категориями. Backend-поддержка
  `groupId` (валидация, ответ) при этом реализуется полностью.

## Тестирование

- **Backend (Testcontainers):** CRUD групп (личные/семейные); валидация при привязке категории
  (группа того же типа и scope, иначе ошибка); разгруппировка категорий при удалении группы
  (FK SET NULL); права на семейные группы (CHILD → 403, ADULT/OWNER ок); изоляция scope.
- **Frontend (mocktail):** репозиторий групп (list/create/delete, маппинг, ошибки).

## Вне объёма (фиксируем явно)

- Вложенные группы (дерево) и many-to-many «категория во многих группах».
- Системный сидинг групп.
- Лимиты/бюджеты на группы — следующая подсистема (будет ссылаться на `category_groups`).
- Авто-категоризация — третья подсистема.

## Известные технические заметки

- Нумерация миграций продолжается с V10 (семейный бюджет занял V8–V9).
- Авто-разгруппировка завязана на FK `categories.group_id ... ON DELETE SET NULL`.
- Группы переиспользуют `HouseholdContextService` (личное/семейное + права) из семейного бюджета.
