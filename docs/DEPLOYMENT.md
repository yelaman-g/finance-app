# Развёртывание AIFB

Инструкция по поднятию сервиса с нуля: база данных → бэкенд → демо-данные → фронтенд.

## 1. Требования

| Компонент | Версия | Проверка |
|---|---|---|
| Docker (+ Compose) | любой актуальный | `docker --version` |
| JDK | 21 | `java -version` |
| Flutter SDK | 3.4+ (Dart 3.x) | `flutter --version` |
| Python | 3.8+ (только для сидера) | `python3 --version` |

`JAVA_HOME` для бэкенда (macOS):
`export JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk-21.jdk/Contents/Home`

## 2. База данных (PostgreSQL)

```bash
docker compose -f deploy/docker-compose.yml up -d
```

Поднимает `postgres:16` (контейнер `aifb-db`, бд/пользователь/пароль = `aifb`, порт `5432`, данные в томе `aifb-pgdata`). Эквивалент без compose:

```bash
docker run -d --name aifb-db -p 5432:5432 \
  -e POSTGRES_DB=aifb -e POSTGRES_USER=aifb -e POSTGRES_PASSWORD=aifb \
  -v aifb-pgdata:/var/lib/postgresql/data postgres:16
```

## 3. Бэкенд (Spring Boot)

Схему создаёт **Flyway автоматически** при старте (миграции `V1…V16`), отдельных DDL-команд запускать не нужно.

```bash
cd backend
JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk-21.jdk/Contents/Home ./gradlew bootRun
```

Слушает `http://localhost:9090` (API под `/api/v1`). Настройки БД переопределяются переменными окружения:

| Переменная | По умолчанию |
|---|---|
| `DB_URL` | `jdbc:postgresql://localhost:5432/aifb` |
| `DB_USER` | `aifb` |
| `DB_PASSWORD` | `aifb` |

Проверка готовности: `curl -i http://localhost:9090/api/v1/auth/me` → `401` (сервис жив, нужен токен).

## 4. Демо-данные

После старта бэкенда (схема уже создана) загрузите демонстрационный набор:

```bash
python3 deploy/seed_demo.py
```

> **Почему через API, а не SQL-дамп.** Системные категории создаёт миграция Flyway V4 со **случайными** UUID (`gen_random_uuid()`), поэтому при каждом развёртывании их идентификаторы разные. SQL-дамп со ссылками на эти id сломался бы на новой базе. Сидер резолвит категории по имени в рантайме и потому переносим между средами; пароли при этом хешируются бэкендом (BCrypt). Скрипт идемпотентен: пользователи/семья создаются один раз, повторный запуск наполнение не дублирует.

Переменные: `AIFB_API` (по умолчанию `http://localhost:9090/api/v1`), `AIFB_PWD` (по умолчанию `password1`).

**Что создаётся** (см. раздел «Снимок данных» ниже):
- 3 пользователя одной семьи (OWNER/ADULT/CHILD), пароль `password1`;
- операции за последние 4 месяца (личные + семейные);
- 8 целей с разным прогрессом (включая завершённую и пустую);
- лимиты со всеми статусами (OK / WARNING / EXCEEDED);
- группа категорий и правила авто-категоризации.

## 5. Фронтенд (Flutter Web)

Для демонстрации надёжнее всего отдавать собранный release-бандл статикой (а не `flutter run -d web-server`, который компилирует debug на лету и может показывать белый экран при первой загрузке):

```bash
cd frontend
flutter pub get
flutter build web --release
python3 -m http.server 3000 --bind 127.0.0.1 \
  --directory build/web
```

Открыть `http://localhost:3000`. Базовый URL API читается из `frontend/.env`
(`API_BASE_URL`), значение по умолчанию — `http://localhost:9090/api/v1`. Чтобы
указать другой хост, отредактируйте `frontend/.env` перед сборкой:

```dotenv
API_BASE_URL=http://<host>:9090/api/v1
```

> Для web-сборки `.env` должен быть объявлен ассетом в `frontend/pubspec.yaml`
> (секция `flutter: assets:`), иначе берётся значение по умолчанию
> (`http://localhost:9090/api/v1`).

Вход в демо: `owner_mail@mail.ru` / `adult_mail@mail.ru` / `child_mail@mail.ru`, пароль `password1`.

## 6. Снимок и резервное копирование БД

Демо-данные восстанавливаются сидером (п. 4) — это основной способ. Для точного слепка **конкретного экземпляра** (та же версия схемы):

```bash
# Снять дамп (схема + данные)
docker exec aifb-db pg_dump -U aifb aifb > backup.sql

# Восстановить в пустую БД
docker exec -i aifb-db psql -U aifb -d aifb < backup.sql
```

Дамп включает таблицу `flyway_schema_history`, поэтому после восстановления бэкенд при старте видит миграции применёнными и конфликтов не возникает.

## 8. Типичные проблемы

| Симптом | Причина / решение |
|---|---|
| Белый экран фронта | Используется `flutter run -d web-server` (debug на лету). Соберите release и отдавайте статикой (п. 5); жёсткое обновление `Cmd/Ctrl+Shift+R`. |
| `401` на всех запросах | Истёкший/некорректный токен — войти заново. На публичных `/auth/**` это норма без токена. |
| Лимиты показывают 0 потрачено | «Потрачено» считается за **текущий месяц**. Сидер добавляет расходы под лимиты на сегодняшнюю дату — запускайте сидер на актуальной системной дате. |
| Бэкенд не стартует, `missing table` | БД не поднята/недоступна — проверьте контейнер и `DB_URL`. |
| Порт 9090/3000/5432 занят | Освободите порт или переопределите (`server.port`, порт http.server, маппинг docker). |

## 9. Google Sign-In (быстрая регистрация)

Вход через Google: фронтенд получает Google ID-token и шлёт его на
`POST /api/v1/auth/google`; бэкенд верифицирует токен, находит/создаёт/привязывает
пользователя и выдаёт обычную JWT-сессию. Управляется двумя переменными окружения
(одинаковые имена на бэкенде и во фронтенде):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `GOOGLE_DEV_MODE` | `true` | Dev-режим: бэкенд принимает неподписанный тестовый токен (`dev.<base64url(JSON)>`), фронтенд не вызывает реальный плагин. Позволяет демонстрировать вход через Google **без реального Google-проекта**. |
| `GOOGLE_CLIENT_ID` | (пусто) | OAuth 2.0 Client ID (web/server-клиент из Google Cloud Console). Нужен только когда `GOOGLE_DEV_MODE=false`. |

**Демо / защита (по умолчанию):** ничего настраивать не нужно —
`GOOGLE_DEV_MODE=true`, кнопка «Войти через Google» создаёт демо-аккаунт через
dev-токен. Это аналог dev-кода в восстановлении пароля и **небезопасно для
продакшна**.

**Продакшн:** задайте `GOOGLE_DEV_MODE=false` и реальный `GOOGLE_CLIENT_ID`
(web/server OAuth client). Бэкенд проверяет подпись/`aud`/срок токена; при пустом
`GOOGLE_CLIENT_ID` в этом режиме приложение падает на старте (fail-fast — чтобы
случайно не принять токен любого приложения). Для Android создаётся **отдельный**
OAuth-клиент с SHA-1-отпечатком подписи, но во Flutter `serverClientId` = тот же
web/server Client ID (чтобы Android вернул `idToken` для серверной верификации).

Frontend читает эти переменные из `frontend/.env` (объявлен ассетом в pubspec, см.
п. 5). Backend — из окружения/`application.yml` (`aifb.google.*`).

> **Известное ограничение.** При крайне маловероятном одновременном *самом первом*
> входе одного и того же нового Google-аккаунта (например, двойной тап) возможен
> конфликт уникального индекса `google_subject` → `HTTP 500` на одном из запросов;
> повторный вход проходит штатно (пользователь уже создан). Для демо не критично;
> промышленное решение — ретрай вставки в отдельной транзакции.

## 10. ИИ-помощник по финансам (Claude API)

ИИ-помощник (чат о финансах, анализ бюджета, инсайты, план накоплений,
напоминания) работает на Anthropic Claude API. Эндпоинты `/api/v1/ai/**`
требуют JWT; финансовый контекст собирает сам backend по текущему пользователю.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `AI_DEV_MODE` | `true` | Dev-режим: детерминированные ответы из реальных финданных **без сети и без ключа** (для тестов/демо). Реальный Claude отключён. |
| `ANTHROPIC_API_KEY` | (пусто) | Ключ Anthropic. Нужен только при `AI_DEV_MODE=false`. |
| `ANTHROPIC_MODEL` | `claude-sonnet-4-6` | Модель Claude (по ТЗ; меняется одной переменной). |
| `AI_MAX_TOKENS` | `2048` | Лимит токенов ответа. |

**Демо / тесты (по умолчанию):** настраивать ничего не нужно —
`AI_DEV_MODE=true`, помощник отвечает осмысленно, считая из реальной статистики
пользователя. Backend-ИТ выполняются без сети и без ключа.

**Продакшн:** задайте `AI_DEV_MODE=false` и реальный `ANTHROPIC_API_KEY`
(`ANTHROPIC_MODEL` при желании). При пустом ключе в этом режиме приложение падает
на старте (fail-fast). **Не вставляйте ключ в код/историю** — только в окружение.
Конфиг — namespace `aifb.ai.*` в `application.yml`.

> **Отложено к этапу FCM (этап 5 ТЗ).** Проактивная push-доставка напоминаний о
> событиях (за 90/30/7/1 дней) требует Firebase Cloud Messaging и device-токенов и
> в этой версии не реализована. Данные напоминаний, расчёт «сколько откладывать» и
> их отображение доступны в приложении (вкладка «Напоминания» экрана ИИ-помощника);
> FCM подключится к готовому полю `notify_days_before` позже.

## 11. Семейный календарь (события)

Общие семейные события (дни рождения, встречи, расписание) с повторениями.
Эндпоинты `/api/v1/events` (под JWT): `GET ?from=&to=&scope=` (повторения
раскрываются на сервере в запрошенный диапазон), `POST/PUT/DELETE`. Миграция V16
(`events`). На фронте — месячная сетка (`table_calendar`) на экране «Календарь»
(вход из «Ещё»), список событий выбранного дня + форма создания. Сетка
показывает личные и семейные события вместе (запрашиваются оба scope и
сливаются); в форме переключатель «Семейное событие» создаёт общую запись семьи.

- **Разовое событие с бюджетом** автоматически создаёт связанное AI-напоминание
  (накопления к дате); удаление события удаляет напоминание. У повторяющихся
  событий бюджет недоступен (попытка → `400 VALIDATION_FAILED`).
- Удаление — **серией целиком**, по тапу с подтверждением (для повторяющихся
  явно сказано «вся серия»). Эндпоинт правки `PUT /events/{id}` есть на бэкенде;
  форма правки в UI отложена (создание + удаление + просмотр — ядро версии).
- Настройки/ключей не требует. Push о событиях — этап FCM (как и AI-напоминания).
